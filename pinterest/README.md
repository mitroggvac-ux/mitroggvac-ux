# Pinterest: система роста аккаунта

Плейбук + рабочий тулкит для системной раскачки Pinterest-аккаунта как медиа:
семантика → план публикаций → тексты → публикация через Pinterest API v5 →
отчёт с решениями.

Папка самодостаточна — её можно целиком перенести в другой репозиторий.

## Что внутри

```
pinterest/
├── docs/                     # плейбук: стратегия, SEO, контент, метрики, риски
├── config/
│   ├── account.example.json  # шаблон конфига: ниша, доски, кластеры ключей, ритм
│   └── ideas.example.json    # формат входных идей для планировщика
├── src/pinterest_kit/        # тулкит (Python 3.11+, только стандартная библиотека)
├── tests/                    # 75 тестов
└── data/                     # очередь, токены, снапшоты аналитики (в .gitignore)
```

## Быстрый старт

```bash
cd pinterest
pip install -e .                    # ставит команду pk; зависимостей нет
# или без установки: export PYTHONPATH=src && python3 -m pinterest_kit ...

pk init                             # config/account.json из примера
$EDITOR config/account.json         # ниша, доски, кластеры ключей, ритм
pk validate                         # проверит конфиг и покажет ёмкость плана
```

Дальше — авторизация (см. [01-account-setup.md](docs/01-account-setup.md)):

```bash
export PINTEREST_APP_ID=... PINTEREST_APP_SECRET=... \
       PINTEREST_REDIRECT_URI=https://localhost/callback PINTEREST_SANDBOX=1

pk auth-url                         # открыть, подтвердить, скопировать ?code=
pk auth-exchange <code>
pk auth-check                       # должен показать ваш аккаунт
pk boards-sync --apply              # создать доски и секции из конфига
```

Рабочий цикл недели:

```bash
pk plan -i config/ideas.example.json --start 2026-08-05 --days 14
pk copy --check                     # предупреждения по текстам
pk calendar --days 7                # что и когда выходит
pk publish                          # сухой прогон
pk publish --apply                  # публикация
pk pull --days 30 && pk report      # аналитика и отчёт с рекомендациями
```

## Команды

| Команда | Что делает |
|---|---|
| `pk init` | Создать `config/account.json` из примера |
| `pk validate` | Проверить конфиг, показать ёмкость плана и запас семантики |
| `pk plan -i ideas.json` | Разложить идеи по датам, доскам и кластерам + сгенерировать тексты |
| `pk copy --check` | Показать проблемы текстов, ничего не меняя (`--force` — пересобрать) |
| `pk status [--state failed]` | Состояние очереди |
| `pk calendar --days 7` | Ближайшие публикации по дням |
| `pk auth-url` / `auth-exchange` / `auth-check` | OAuth и проверка токена |
| `pk boards-sync [--apply]` | Сверить доски конфига с аккаунтом, создать недостающие |
| `pk publish [--apply]` | Опубликовать то, чему пришло время (по умолчанию — сухой прогон) |
| `pk retry` | Вернуть упавшие пины в очередь |
| `pk pull --days 30` | Снять аналитику аккаунта и пинов в `data/analytics/` |
| `pk report -o report.md` | Markdown-отчёт: факт против целей + что чинить |

Все команды, меняющие что-то на стороне Pinterest, по умолчанию работают
в режиме сухого прогона — нужен явный `--apply`.

## Как это устроено

```
config/account.json          ideas.json
   (ниша, доски,          (id, хук, картинка,
    кластеры, ритм)          ссылка)
        │                        │
        └────────► pk plan ◄──────┘
                      │  раскладка по датам/доскам + тексты из шаблонов
                      ▼
              data/queue.json  ──► pk publish --apply ──► Pinterest API v5
                      ▲                                          │
                      │                                          ▼
              pk report ◄──── data/analytics/ ◄──── pk pull ◄────┘
                      │
                      └─► решения: каким кластерам дать больше слотов
```

Модули: `config` (конфиг и валидация), `keywords` (кластеры и ротация ключей),
`copywriter` (тексты + проверки), `scheduler` (календарь), `store` (очередь
и снапшоты), `api` (клиент v5), `publisher` (доски и публикация),
`analytics` (метрики), `report` (отчёт), `cli`.

Что тулкит проверяет за вас: лимиты Pinterest на длину полей, наличие ключа
в заголовке и описании, переспам, дневной лимит на доску, паузы между
публикациями, соответствие пина кластеру доски, кластеры без единого пина,
исчерпание списка хвостов.

## Ограничения

- Pinterest не публикует алгоритм ранжирования. В документах помечено, где
  факт из официальной документации, а где практика.
- Новые приложения работают в trial/sandbox: пины создаются, но наружу не
  публикуются. Полный доступ требует ревью Pinterest.
- Тулкит не рисует обложки — он планирует, пишет тексты, публикует и считает.
  Производство визуала описано в [03-content-system.md](docs/03-content-system.md).
- `data/token.json` содержит секреты и создаётся с правами `600`. В git не идёт.
