# 02. Семантика: где брать ключи и куда их вшивать

Pinterest сопоставляет запрос пользователя с текстом пина, названием и описанием
доски, текстом **на самой картинке** (распознаётся) и поведением людей, которые
этот пин уже видели. Всё, кроме поведения, вы контролируете напрямую.

## Где брать ключи (по убыванию полезности)

### 1. Автоподсказки поиска Pinterest — главный источник

Вбиваете корневое слово в поиск и смотрите выпадающий список. Это реальные
запросы реальных пользователей Pinterest, а не выгрузка из Google, где спрос
устроен иначе.

Метод «в глубину»: `пляжи кипра` → берёте каждую подсказку → вбиваете её →
собираете следующий уровень. Двух проходов хватает на 30–50 хвостов.

### 2. Цветные плитки под строкой поиска

После ввода запроса Pinterest показывает ряд плиток-уточнений (`с детьми`,
`осенью`, `недорого`). Это готовая карта модификаторов от самого Pinterest —
самый быстрый способ понять, чем люди уточняют вашу тему.

### 3. Pinterest Trends

`trends.pinterest.com` — сезонность и динамика запросов по странам. Главная
ценность — **когда** публиковать: Pinterest рекомендует заходить с сезонной
темой **за 30–45 дней** до пика (факт). Летние маршруты ставятся в апреле,
новогоднее — в начале ноября.

### 4. Что уже работает у вас

Из `pk report` → раздел «Кластеры ключей». Кластер с высоким save rate
разворачивается в под-темы: это спрос, который вы уже подтвердили на своей
аудитории, а не гипотеза.

### 5. Конкуренты

Открываете 3–5 аккаунтов вашей ниши, смотрите названия досок и заголовки
верхних пинов. Не копировать — вылавливать формулировки, до которых сами
не додумались.

## Как собрать кластер

Кластер — это **одна подтема** с одним `head` и 5–15 длинными хвостами.

```json
"beaches": {
  "head": "пляжи кипра",
  "terms": [
    "лучшие пляжи Кипра",
    "тихие пляжи Кипра без толпы",
    "пляжи Кипра с песком",
    "пляжи Айя-Напы",
    "дикие пляжи Пафоса",
    "пляжи Кипра для детей"
  ],
  "hashtags": ["Кипр", "пляжиКипра", "отдыхНаКипре"]
}
```

Правила, которые экономят месяцы:

- **`head` — то, чем тема называется в поиске**, а не ваш внутренний термин.
- **Хвост из 3–5 слов бьёт однословник.** По `Кипр` вы не встанете никогда,
  по `тихие пляжи Кипра без толпы` — вполне.
- **Один хвост = один пин.** Не пытайтесь впихнуть три ключа в одно описание:
  тулкит пометит это как переспам, и он будет прав.
- **5–15 хвостов на кластер.** Меньше 3 — `pk validate` не пропустит: описания
  начнут повторяться. Больше 15 — кластер пора делить надвое.
- **4–8 кластеров на аккаунт.** Это ширина ниши. Больше — фокус размывается.

Проверить наполненность семантики:

```bash
pk validate    # покажет число кластеров, термов и ёмкость плана
```

Если предупреждение «термов мало относительно объёма публикаций» — сначала
расширяйте семантику, потом наращивайте объём. Иначе будете публиковать
разные картинки под одинаковыми текстами.

## Куда вшивать ключи

| Место | Лимит | Что писать |
|---|---|---|
| Заголовок пина | 100 симв. | Ключ + конкретная выгода. Первые 40 симв. видны в ленте |
| Описание пина | 500 симв. | Ключ в первом предложении, дальше — польза и повод сохранить |
| Alt-текст | 500 симв. | Что изображено, своими словами, с ключом |
| **Текст на картинке** | — | Крупно, 3–6 слов. Распознаётся Pinterest и решает, кликнут ли |
| Имя доски | 50 симв. | Ключ кластера в человеческой форме |
| Описание доски | 500 симв. | 2–3 предложения с ключами кластера |
| Имя профиля | 65 симв. | Бренд + главный ключ ниши |

Всё, что в таблице касается пина, тулкит собирает сам:

```bash
pk plan -i ideas.json    # разложит по кластерам и сгенерирует тексты
pk copy --check          # покажет проблемы, ничего не переписывая
```

Проверки, которые делает `pk copy --check`:

- ключа нет в заголовке → Pinterest хуже поймёт тему;
- нет точного вхождения ключа в описании;
- ключ повторён 3+ раза → переспам;
- заголовок короче 20 симв. или капсом;
- описание короче 100 симв. → недобираете охват;
- пустой alt-текст.

## Хэштеги

Роль у них вспомогательная, а не решающая. **3 штуки максимум**, в конце
описания, по теме кластера. Двадцать хэштегов в описании — это сигнал спама
и вытеснение полезного текста, а не буст.

## Частая ошибка

Люди собирают семантику один раз на старте и больше к ней не возвращаются.
Правильный цикл — раз в месяц:

1. `pk report` → посмотреть, какие кластеры вытягивают, а какие мертвы;
2. рабочий кластер разложить на под-темы, добавить хвостов;
3. мёртвый — либо переписать подачу, либо убрать из ротации (`weight` доски);
4. пройтись по автоподсказкам заново: спрос сезонный и меняется.
