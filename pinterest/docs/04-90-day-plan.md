# 04. План на 90 дней

Три фазы: **фундамент** (недели 1–2), **накопление** (недели 3–8),
**оптимизация** (недели 9–13). Раньше 60-го дня стратегические решения по данным
не принимаются — статистики просто нет.

---

## Фаза 1. Фундамент (недели 1–2)

Цель — чтобы Pinterest понял, о чём аккаунт. Трафика на этом этапе не будет,
и это не повод что-то менять.

### Неделя 1 — настройка

- [ ] Бизнес-аккаунт, профиль с ключами в имени и About
- [ ] Домен подтверждён, Rich Pins прошли валидатор
- [ ] Нерелевантные старые доски → SECRET
- [ ] Семантика: 4–8 кластеров по 5–15 хвостов (`pk validate` без ошибок)
- [ ] 3–5 шаблонов обложек 1000×1500
- [ ] `pk boards-sync --apply` — доски и секции созданы
- [ ] Первые 20–25 пинов подготовлены (обложки + `ideas.json`)

**Публикация: 3 пина в день.** Не больше — новый аккаунт с 30 пинами в сутки
выглядит как ферма.

```bash
pk validate
pk boards-sync --apply
pk plan -i ideas/week-01.json --start $(date +%F) --days 7
pk copy --check
pk publish            # сухой прогон
pk publish --apply
```

### Неделя 2 — выход на ритм

- [ ] Довести до 5 пинов в день
- [ ] Каждый кластер получил хотя бы 3 пина
- [ ] Пакетное производство: 40 обложек за один заход
- [ ] Проверить, что все доски заполнены (пустая доска — мёртвый вес)

**Метрика недели:** ноль. Смотреть только на то, что публикации проходят без
ошибок: `pk status --state failed`.

---

## Фаза 2. Накопление (недели 3–8)

Цель — объём и стабильность. Здесь появляются первые показы.

### Ежедневно (10 минут)

```bash
pk publish --apply       # опубликовать наступившее
pk status --state failed # разобрать упавшее
```

### Еженедельно (2 часа)

- [ ] Пакет из 35–50 новых обложек
- [ ] `pk plan -i ideas/week-NN.json --days 14`
- [ ] `pk copy --check` — исправить замечания
- [ ] `pk calendar --days 7` — проверить раскладку
- [ ] С недели 4: `pk pull --days 14 && pk report`

### Контрольные точки

| Неделя | Что должно быть | Если нет |
|---|---|---|
| 3 | Первые показы в аналитике | Проверить, что пины публичные и домен подтверждён |
| 4 | 100+ пинов всего | Нарастить производство, а не ключи |
| 6 | Виден первый «выстреливший» пин | Проблема в креативе: пересобрать шаблоны |
| 8 | Показы растут неделя к неделе | См. [05-metrics.md](05-metrics.md) |

**Объём:** недели 3–4 — 5 пинов в день, недели 5–8 — 7–10, если производство
тянет. Наращивать плавно, не рывком.

### Чего не делать в этой фазе

- Не менять нишу и не добавлять кластеры «на пробу»
- Не удалять «неудачные» пины
- Не делать пауз дольше 2 дней
- Не принимать решений по данным одной недели

---

## Фаза 3. Оптимизация (недели 9–13)

Данных достаточно, чтобы перераспределять усилия.

### Неделя 9 — первый серьёзный разбор

```bash
pk pull --days 60 --pins 100
pk report -o data/report-90d.md
```

Разобрать по отчёту:

1. **Топ-10 пинов.** Что общего: формат, тема, тип обложки, время выхода?
2. **Кластеры.** Кто в лидерах по save rate, а не по показам?
3. **Аутсайдеры.** Кластер с 5+ пинами и save rate ниже 0.5% — проблема
   в подаче или в спросе.

### Недели 10–13 — действия по данным

| Что видно в отчёте | Что делать |
|---|---|
| Кластер тянет | `weight` его доски +1, разложить на под-темы, добавить хвостов |
| Кластер мёртв | Сменить подачу; не помогло за 3 недели — убрать из ротации |
| Показы есть, сохранений нет | Проблема в обложке: 3 новых варианта на тот же ключ |
| Сохранения есть, кликов нет | Пин закрывает тему целиком — оставить открытый вопрос |
| Формат выстрелил | Долю формата в неделе — вдвое |

**Расширение ниши** — не раньше недели 12 и только в соседний кластер,
подтверждённый данными.

## Итоги 90 дней: реалистичные ориентиры

Для нового аккаунта без разгона рекламой и без внешнего трафика:

| Показатель | Слабо | Норма | Хорошо |
|---|---|---|---|
| Пинов опубликовано | < 300 | 400–600 | 600+ |
| Показов в месяц (3-й мес.) | < 10k | 30–80k | 150k+ |
| Save rate | < 0.3% | 0.5–1% | 1.5%+ |
| Подписчиков | < 100 | 200–600 | 1000+ |

Разброс здесь огромен и сильно зависит от ниши: конкурентные темы (рецепты,
интерьеры) растут дольше, узкие гео-темы — быстрее. Ориентируйтесь на **свою
динамику неделя к неделе**, а не на чужие скриншоты.

## Ежедневная / недельная / месячная рутина

**Каждый день (10 мин):** `pk publish --apply`, разобрать `failed`.

**Каждую неделю (2 ч):** пакет обложек → `pk plan` → `pk copy --check` →
`pk calendar`.

**Каждый месяц (1 ч):** `pk pull --days 30 && pk report` → перераспределить
`weight` досок → обновить семантику по автоподсказкам → заложить сезонные темы
на 30–45 дней вперёд.
