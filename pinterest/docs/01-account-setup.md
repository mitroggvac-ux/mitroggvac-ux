# 01. Настройка аккаунта и доступ к API

Разовая работа на 1–2 часа. Пока она не сделана, всё остальное считать
преждевременным: без бизнес-аккаунта нет аналитики, без подтверждённого домена
нет атрибуции, без Rich Pins ваши пины выглядят беднее конкурентов.

## Шаг 1. Бизнес-аккаунт

1. Личный аккаунт конвертируется в бизнес бесплатно: **Settings → Account
   management → Convert to business account** (или создать новый business).
2. Заполнить профиль так, чтобы он читался как медиа по конкретной теме:
   - **Имя (до 65 симв.)**: `Название | главный ключ`. Например,
     `Cyprus Guide | пляжи, маршруты, переезд`. Имя индексируется — не тратьте
     его на пустой брендинг.
   - **About (до 500 симв.)**: одним абзацем — о чём аккаунт, для кого, что
     человек получит. Ключи вписаны в живую речь, а не перечислены списком.
   - **Аватар**: узнаваемый, читается в 32 px.
3. Указать сайт и включить его отображение в профиле.

## Шаг 2. Подтверждение домена (claim website)

**Settings → Claimed accounts → Claim website.** Три способа: HTML-тег в `<head>`,
загрузка HTML-файла в корень, или TXT-запись в DNS.

Зачем это нужно (факт):
- ваш логотип и подпись появляются на всех пинах, ведущих на домен, даже если
  пин сохранил кто-то другой;
- открывается аналитика по домену, а не только по вашим пинам;
- это предусловие для Rich Pins.

## Шаг 3. Rich Pins

Rich Pins подтягивают в пин метаданные прямо с вашей страницы (заголовок,
описание, автор, цена для товаров). Тип определяется разметкой на странице:

```html
<!-- Article Rich Pin: Open Graph в <head> -->
<meta property="og:type"        content="article" />
<meta property="og:title"       content="Тихие пляжи Кипра: 7 бухт без толпы" />
<meta property="og:description" content="Где купаться на Кипре в разгар сезона..." />
<meta property="og:url"         content="https://example.com/cyprus/quiet-beaches" />
<meta property="og:image"       content="https://example.com/img/quiet-beaches.jpg" />
<meta property="article:author" content="Имя Автора" />
```

Проверка и заявка: **Rich Pins Validator** в разделе для разработчиков —
вставляете URL любой страницы с разметкой, получаете подтверждение. Одобрение
распространяется на весь домен, повторять для каждой страницы не нужно.

> Важно: заголовок Rich Pin с вашей страницы может перекрыть заголовок пина.
> Держите `og:title` тоже осмысленным и ключевым.

## Шаг 4. Доски

Доски — это не папки для себя, а посадочные страницы под кластеры. Каждая:

- **Имя (до 50 симв.)**: человеческое, с ключом. `Пляжи Кипра` — да,
  `Мои находки ✨` — нет.
- **Описание (до 500 симв.)**: 2–3 предложения с ключами кластера в живой речи.
  Описание доски индексируется.
- **Категория** — выбрать ближайшую.
- **Секции** — для крупных досок (по гео, по формату, по сезону).

Стартовый набор: 4–8 досок. Меньше — узко, больше — размывается фокус и
нечем их наполнять.

Всё это описывается в `config/account.json` один раз, а создаётся командой:

```bash
pk boards-sync          # показать, что будет создано
pk boards-sync --apply  # создать недостающие доски и секции
```

Доски со старого личного аккаунта, не относящиеся к нише, — **в SECRET**,
не удаляя. Публичный профиль должен читаться как один тематический медиа-канал.

## Шаг 5. Приложение в Pinterest Developers (для API)

Нужно, только если публикуете и снимаете аналитику через тулкит.

1. Зайти на **developers.pinterest.com** под своим бизнес-аккаунтом → **My apps**
   → создать приложение. Понадобится описание сценария использования.
2. Указать **Redirect URI** — для локальной работы подойдёт
   `https://localhost/callback` (реальный сервер не нужен: код вы скопируете
   из адресной строки).
3. Забрать **App ID** и **App secret**.
4. Новые приложения стартуют в режиме **trial/sandbox**. В песочнице пины
   создаются, но наружу не публикуются — это ровно то, что нужно для проверки
   пайплайна. Полный доступ запрашивается отдельно и требует ревью Pinterest,
   так что закладывайте на это время.

### Переменные окружения

```bash
export PINTEREST_APP_ID="1234567"
export PINTEREST_APP_SECRET="..."
export PINTEREST_REDIRECT_URI="https://localhost/callback"
export PINTEREST_SANDBOX=1        # 1 — песочница, 0 или пусто — прод
```

### Авторизация

```bash
pk auth-url                  # открыть ссылку, подтвердить доступ
                             # из адреса редиректа скопировать ?code=...
pk auth-exchange <code>      # обменять код на токены → data/token.json
pk auth-check                # проверить: покажет username и счётчики
```

Что происходит под капотом (факт, по документации Pinterest v5):

- токены выдаёт `POST https://api.pinterest.com/v5/oauth/token` с HTTP Basic
  авторизацией (`client_id:client_secret` в base64);
- access token живёт **30 дней**, refresh token в режиме continuous refresh —
  **60 дней с бесконечным продлением**;
- тулкит обновляет access token автоматически за 5 минут до истечения, поэтому
  руками `refresh` дёргать не нужно.

Запрашиваемые скоупы: `user_accounts:read`, `boards:read`, `boards:write`,
`pins:read`, `pins:write`. Меньше не даст работать публикации и аналитике,
больше — не нужно.

### Безопасность

- `data/token.json` содержит секреты, создаётся с правами `600` и уже внесён
  в `.gitignore`. **Не коммитить.**
- `PINTEREST_APP_SECRET` — в переменные окружения или менеджер секретов, не в конфиг.
- При компрометации: в кабинете разработчика перевыпустить secret, затем
  заново пройти `auth-url` → `auth-exchange`.

## Чек-лист готовности

- [ ] Бизнес-аккаунт, профиль заполнен с ключами в имени и About
- [ ] Домен подтверждён (claimed)
- [ ] Rich Pins прошли валидатор
- [ ] 4–8 досок с ключевыми именами и описаниями
- [ ] Нерелевантные старые доски скрыты
- [ ] `pk validate` проходит без ошибок
- [ ] `pk auth-check` показывает ваш аккаунт
